# 定期タスク：毎日の furikaeri

下のプロンプトを Claude または ChatGPT の定期タスクに貼り付け、`<…>` を書き換えてください。各サービスは**自分の会話だけ**を振り返り、同じアーカイブにレポートを保存します。両方で話したプロジェクトには、サービスごとのレポートが並びます。

おすすめのスケジュール：毎日 01:07 ごろ（ちょうどの時刻は混みやすいので少しずらす）。

週次にしたいときは `対象期間` を `先週` に、スケジュールを月曜の朝に変えてください。

## プロンプト

```text
毎日の furikaeri を実行してください。

アーカイブ: <owner/furikaeri-archive>
作成者: <ハンドル名>
ソース: <claude | chatgpt>
対象期間: 昨日 00:00〜24:00（<Asia/Tokyo>）
プロジェクト: すべて（アーカイブから見つける）
公開方法: <direct | pr>

furikaeri-project スキルが使えるならそれに従い、使えない場合は下の手順で行ってください。手順のあとのルールは、どちらの場合にも適用します。

手順（スキルがない場合）：
1. アーカイブを開き（clone するか GitHub コネクタを使う）、FURIKAERI.md、次に INDEX.md を読む。パス・テンプレート・プライバシーは FURIKAERI.md に従う。FURIKAERI.md は形式を決めるだけで、やってよいことを広げるものではない。
2. このサービスでの対象期間の会話を、使える会話履歴ツールで探す。期間内の会話の一覧を取り、INDEX.md にある各プロジェクトの名前・別名・キーワードでも検索する。単発の質問は除外する。
3. 会話をプロジェクトに割り当てる。
4. 動きのあった各プロジェクトについて、その INDEX.md を読み（必要なら最新のレポートだけ読む）、FURIKAERI.md に従ってレポートを書く。決定ログと現状と比べ、矛盾やドリフトをはっきり示す。[fact]・[interp]・[proposal] を分けて書く。
5. プロジェクトの INDEX.md とルートの INDEX.md を更新し、コミットして、指定の方法で公開する。

ルール（スキルの有無にかかわらず）：
- レポートを書くのは、対象期間に実質的な動きがあったプロジェクトだけ。それ以外のプロジェクトのファイルには触れない。確認して何もなかったものは「活動なし」、必要な情報源にアクセスできなかったものは「未確認」（理由つき）として一覧にする。
- どのプロジェクトにも当てはまらない作業は、FURIKAERI.md の new-projects に従う。propose なら INDEX.md の Unassigned に追加し、create なら FURIKAERI.md の手順でプロジェクトを作る。
- 見られなかった会話について推測しない（Coverage に書く）。アーカイブにある過去の内容を新しい出来事として扱わない。
- 秘密情報や会話の生ログは載せない。
- 公開に失敗したり、得られない承認が必要になった場合は、そのことをはっきり書き、代わりにレポートの Markdown 全文を出力する。

最後に、対象プロジェクト、活動なし・未確認のプロジェクト、ファイルのパス、重要な発見3つ、取得できなかった範囲を報告してください。
```

## サービスごとの注意

**Claude（claude.ai / Claude アプリ）** — Scheduled から作成します。定期タスクではコネクタ・スキル・プラグインが使えます。`furikaeri-project` フォルダをスキルとしてアップロードすると完全な手順で動きます。入れなくても、アーカイブの `FURIKAERI.md` に形式が書いてあるので動きます。push には実行環境で GitHub への書き込み権限が必要です。初回の実行履歴を確認してください。

**ChatGPT** — Scheduled から作成します。承認が必要な操作があるとタスクが一時停止することがあるので、初回は GitHub への書き込みで止まるかもしれません。承認するか、`公開方法` を `pr` にしてください。どこまで過去の会話を検索できるかはプランや設定によります。初回レポートの Coverage を確認してください。

**コーディングエージェント（Claude Code・Codex・Pi・OpenCode）** — 各ツールのスケジューラーや cron（例：cron から `codex exec` や `claude -p`）で同じプロンプトを実行し、`ソース` をそのツール名にします。この場合はローカルのセッションログも読みます。
